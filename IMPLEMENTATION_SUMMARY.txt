# UCP Schema Migration - Implementation Summary
Date: 2026-02-11

## Problem Fixed
Merchant verification was failing because the system validated against an outdated UCP manifest schema.
- Old schema expected: products_endpoint, checkout_endpoint, public_key
- Actual UCP manifests use: business_profile, services, capabilities, signing_keys
- Result: All verifications failed even with valid UCP endpoints

Example failure: https://test.zologic.nl/.well-known/ucp returned valid manifest but verification failed

## Solution Implemented
Migrated all validation logic to support the new UCP schema structure with dynamic endpoint discovery.

## Files Created (3 new files)

1. database/migrations/001_add_ucp_business_profile.sql
   - Adds 7 new columns to merchants table:
     * business_name VARCHAR(255)
     * business_description TEXT
     * business_url VARCHAR(500)
     * contact_email VARCHAR(255)
     * service_base_url VARCHAR(500)
     * signing_key_id VARCHAR(255)
     * ucp_manifest JSONB
   - Creates GIN index on ucp_manifest for fast JSONB queries
   - All columns are nullable (non-breaking change)

2. database/migrations/001_add_ucp_business_profile_down.sql
   - Rollback script to remove new columns if needed
   - Drops index and all 7 new columns

3. api/utils/ucpParser.js
   - Centralized UCP manifest parser
   - Export: parseUcpManifest(manifest)
   - Returns: { isValid: boolean, error: string|null, data: object }
   - Validates: business_profile, services, capabilities, signing_keys
   - Extracts: businessName, serviceBaseUrl, publicKey, signingKeyId, etc.
   - Used by: admin.js, verifyMerchants.js

## Validation Logic Changes

### Old Validation (Before)
```javascript
if (!manifest.products_endpoint || !manifest.checkout_endpoint || !manifest.public_key) {
    return { status: 'failed', error: 'Invalid UCP manifest structure' };
}
```

### New Validation (After)
1. Validate business_profile.name exists
2. Find shopping service in services[] array
3. Extract base_url from REST transport
4. Verify capabilities[] contains products and checkout
5. Extract signing key where use === 'sig'
6. Extract x (public key) and kid (key ID)

Result: Detailed error messages for each failure scenario
